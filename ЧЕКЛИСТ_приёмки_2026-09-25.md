# Чек-лист приёмки (25.09.2026)

Ветка: `feat/printsrv-mocks-and-ui-polish` → PR в `main`.
Мок-данные бэкенда обновлены по реальным логам `printsrv-logs/` — все проверки выполнять на dev-режиме с моками.

| № | Что проверить | Где | Критерий приёмки |
|---|---------------|-----|------------------|
| 1 | Переименование карточки | Админка → «Справочники» | Карточка называется «Устройства», а не «Справочник устройств». Остальные карточки («Роли», «Цеха», «Типы устройств») без изменений |
| 2 | Одна кнопка «Сохранить» | Админка → «Справочники» → любой справочник → «Редактирование» | Кнопка «Сохранить» только справа сверху (рядом с «Доп. параметры»). Нижняя левая кнопка удалена. Сохранение работает |
| 3 | Карточка ошибки в Журнале | Детали автомата → вкладка «Журнал» | (а) Технический код (`Dev041Fail` и т.п.) не отображается; (б) вместо него — дата/время возникновения ошибки (как в старой SCADA, см. колонку «Время возникновения»); (в) вертикальная красная полоска слева убрана; (г) закругления слева такие же, как справа. Проверить на автомате с активной ошибкой (например Bosch, Grunwald №5) |
| 4 | Описание партии в одну строку | Детали автомата → вкладка «Партия» | Поле «Описание» не переносится на вторую строку, если хватает места (длинные значения, например «Йог.2%п/ст120гКлубника», отображаются корректно — без обрезки/наложения) |
| 5 | Прочерк вместо пустого значения | Детали автомата → вкладка «Партия» | Поле «Регион» (и любые пустые поля) показывают «—», а не пустую строку |
| 6 | Форма редактирования автомата | Админка → «Автоматы» → редактирование автомата, блок «Раскладка устройств» | У каждого устройства остались только поля «Группа» и «SCADA-префикс». Полей «Имя на экране» и «Порядок» нет. Сохранение формы работает, раскладка на клиенте не ломается |
| 7 | Текущая партия на карточках устройств | Детали автомата → вкладка «Устройства» | На КАЖДОЙ карточке каждого устройства (камеры, принтеры, независимо от настройки видимости счётчиков) отображается текущая партия. Если счётчики включены для устройства — партия + значения счётчиков; если выключены — только партия. Проверить на Grunwald №5 (CamAgregation, CamChecker, камеры 71–74, принтеры) и на автомате со скрытыми счётчиками |
| 8 | Пустой Журнал | Детали автомата → вкладка «Журнал» без активных ошибок | Заголовок «Активные ошибки» чёрный (как «Очередь печати» на вкладке «Очередь»). SVG-иконка слева от текста «Нет активных ошибок» отсутствует. Сам текст «Нет активных ошибок» приглушённого/серого цвета. Стиль соответствует «Очередь пуста» |
| 9 | Счётчики 0/0 на главной | Главная → список автоматов цеха | У Grunwald №5 (где счётчики включены через админку) в строке карточки отображаются реальные значения счётчиков из моков (например «26831 / 109»), а не «0 / 0». Значения совпадают с карточкой камеры в деталях автомата |
| 10 | Сортировка в таблицах админки | Админка → «Сотрудники», «Автоматы», «Справочники» → все таблицы | У каждого столбца есть сортировка по возрастанию/убыванию (клик по заголовку переключает направление, индикатор направления виден). Сортировка комбинируется с существующим поиском по полям |
| 11 | Дубликаты названий устройств | Админка → «Справочники» → «Устройства» | (а) В БД снято ограничение уникальности с поля «Название» — можно создать два устройства с одинаковым названием и разными кодами; (б) в выпадающих списках устройств (например при выборе устройств автомата) одинаковые названия различаются отображением кода, например «Принтер 2 (PRT-002)»; (в) миграция БД применяется без ошибок |
| 12 | Моки = реальные логи | Dev-режим бэкенда целиком | Данные на всех экранах (автоматы, счётчики, ошибки, партии, очередь печати) соответствуют формату реальных данных из `printsrv-logs/`: коды ошибок вида `Dev041Fail`, партии вида «1487 \| 281 \| 26.09.2026», счётчики не нулевые там, где в логах не ноль |
