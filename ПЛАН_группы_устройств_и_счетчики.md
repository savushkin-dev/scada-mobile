# План: группировка устройств, счётчики и имена в ошибках (паритет со старой SCADA)

Основание: [PRINTSRV_UI_MAP.md](PRINTSRV_UI_MAP.md) (доказанные соответствия по реальным логам PrintSrv).
Ветка: `fix/device-counters-grouping`.

## Что исправляем (симптомы)

1. Счётчики «Считано/Несчитано» не совпадают со старой SCADA: фронт показывает `CamChecker.Total/Failed`, а старая SCADA показывает теневые счётчики агрегатора `scada` — `Dev041CounterGeneral/CounterMissing` (первая камера каждого потока, физически `CamAgregation`).
2. `CamAgregation` отсутствует в БД-топологии реальных автоматов → правильной карточки нет вообще; зато `CamChecker` и `CamEanChecker1..4` показывают счётчики, которых старая SCADA не показывает.
3. Нет деления на группы «машина / Поток N / Агрегация» — сейчас 4 жёсткие функциональные секции.
4. Журнал/алерты показывают сырые имена (`Dev041`, `LineDev02`) и дубль от общего флага `Error`.

## Целевые правила (доказаны в карте)

- Считано = `Dev0XXCounterGeneral`, Несчитано = `Dev0XXCounterMissing` (scada-first, как сейчас). Fallback: `Succeeded` (НЕ `Total`) / `Failed` устройства.
- Счётчики видны только устройствам с `showCounters=true`; дефолт — камерам агрегации (`Dev041`, `Dev043`, …).
- Группы устройств — per-unit конфиг в БД; дефолты: принтеры+EAN-камеры → группа с именем автомата; `CamAgregation[Box][N]` → «Поток N» (N из scada-префикса: `Dev04(2k−1)/(2k)` → поток k; если поток один — просто «Поток»); `CamChecker[N]` → «Поток N» без счётчиков.
- Ошибки: человекочитаемое имя = display name устройства (+ префикс группы, если группа не машинная: «Поток 2. Камера 43»); сырой ключ остаётся в `propertyDesc`; флаг `Error` подавляется, если у того же устройства активен конкретный флаг.

## Backend

### B1. Миграция и сущность

Найти механизм миграций в `backend/src/main/resources` (Flyway/Liquibase/schema.sql — уточнить по репозиторию). Таблица `unit_devices` — добавить колонки:

- `display_name VARCHAR NULL` — per-unit переопределение имени (иначе `device_catalog.name`);
- `group_label VARCHAR NULL` — «Поток 2», «Агрегация» и т.п.; NULL = дефолт по правилам;
- `display_order INT NOT NULL DEFAULT 0` — порядок внутри группы;
- `show_counters BOOLEAN NOT NULL DEFAULT FALSE`;
- `scada_prefix VARCHAR NULL` — например `Dev041`, `LineDev011`; NULL = вычислить по ScadaKeyMapper.

Обратная заливка существующих строк: `scada_prefix` по правилам ScadaKeyMapper (aggregation_cam i → `Dev%03d`(41+i*2); aggregation_box_cam i → 42+i*2; CamEanCheckerN → `Dev07N`; PrinterNN → `LineDev0NN`), `show_counters=true` для `aggregation_cam`, `display_order` = текущий порядок.

Обновить `DeviceEntity` (`infrastructure/integration/database/entity/`), `AdminDeviceController` (request/response с новыми полями), `AdminReadController` (выдача layout для `?unitId=`), при необходимости `AdminDataChangeBroadcaster`/DTO.

### B2. Разрешение scada-префикса с учётом конфига

`ScadaKeyMapper`: добавить разрешение префикса устройства: сначала `unit_devices.scada_prefix`, затем существующие индексные правила. Все места, где префикс вычисляется индексом (`UnitDetailService.addErrorPrefixes`/`cameraReferences`, `WorkshopService.cameraReferences`, `MockStateSimulator.tickScada`), перевести на единый резолвер (новый бин, например `DeviceScadaRegistry`, строящий карту instanceId → (deviceCode ↔ scadaPrefix) из БД + runtime composition). Mock XML не трогаем (ограничение старого ТЗ).

### B3. Счётчики

- `RuntimeTagMapper.resolveCounters`: fallback камеры — `Succeeded` вместо `Total` (обоснование в карте §2); прямой путь без префикса тоже `Succeeded`/`Failed`. Обновить `RuntimeTagMapperTest`.
- Новый общий компонент (например `DeviceCounterResolver`): resolve(deviceCode, instanceId) → (read, unread, source) по правилу scada-first + fallback. Убрать дублирование `UnitDetailService.resolveCameraCounters` (строки 653–696) и `WorkshopService.resolveCameraCounters` (265–310).
- Агрегат для карточки автомата (`UNITS_STATUS`/`LINE_STATUS` cameraRead/cameraUnread): первая по `display_order` камера с `show_counters=true`; fallback — первая aggregation cam; EAN/checker без флага не участвуют.

### B4. Топология устройств для фронта

`UnitDeviceTopologyDTO` — добавить:

- `groups: [{ label: string, order: number, codes: string[] }]` — машинная группа (label = имя автомата) первой, далее по order; внутри группы сортировка по `display_order`, затем code;
- `deviceMeta: { [code]: { displayName: string, showCounters: boolean } }` — displayName уже с учётом per-unit override.

Существующие `devices`/`deviceNames`/`typeNames` сохранить (deprecated), чтобы не ломать контракт в переходный период. Сборку групп вынести в отдельный сервис с юнит-тестами (дефолты из раздела «Целевые правила» + ручной `group_label`).

### B5. Ошибки: имена и дедупликация

- Новый резолвер имён (можно в том же `DeviceScadaRegistry`/topology-сервисе): scadaPrefix → deviceCode → displayName (+ groupLabel, если группа не машинная: формат `{groupLabel}. {displayName}`).
- `UnitDetailService.extractActiveErrors`: `objectName` = человекочитаемое имя; `propertyDesc` = сырой ключ (как сейчас); дедуп: если у устройства активны конкретные флаги, его голый `Error` в выдачу не включать.
- `WorkshopService.deriveEvent`: те же человекочитаемые имена в строках события.
- Проверить, что `AlertService` берёт ошибки из `UnitErrorStore` — тогда имена в ALERT исправятся автоматически.
- Тексты сообщений оставить (таблица в карте §4 совпадает).

### B6. Авто-discovery

`DeviceAutoDiscoveryService.syncRuntimeDevices`: новые строки `unit_devices` заполнять дефолтами (scada_prefix по типу+индексу, show_counters для aggregation_cam, display_order в конец). Так `CamAgregation` появится на реальных автоматах сама.

### B7. Тесты backend

- `RuntimeTagMapperTest`: fallback `Succeeded/Failed`, приоритет CounterGeneral, override префикса.
- Новые тесты: сборка групп топологии (машина/Поток N/ручная группа/порядок), агрегат unit-счётчиков (выбор showCounters-камеры), дедуп `Error`, человекочитаемые имена ошибок.
