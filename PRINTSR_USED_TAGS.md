# Теги PrintSrv, используемые SCADA Mobile

## Назначение

Документ подготовлен для согласования с отделом маркировки. В нём перечислены поля, которые backend SCADA Mobile получает в ответах PrintSrv `QueryAll` и использует при формировании статусов, ошибок, состава оборудования и данных партии.

Важно: PrintSrv возвращает полный снимок устройства, поэтому фактический набор ключей может быть шире. В документ включены прикладные токены, к которым обращается backend, а также технические поля протокола.

## Как читать список

- **Токен** — точное имя ключа PrintSrv или шаблон имени для группы однотипных ключей.
- **Источник** — устройство PrintSrv, в снимке которого backend ищет ключ.
- **Использование backend** — зачем значение нужно программе.
- **Что видит оператор** — куда значение попадает на фронтенде. Если указано «не выводится», токен всё равно может участвовать во внутренней логике.
- Для значений партии действует приоритет: сначала `BatchQueue`, затем соответствующий принтер как резервный источник.
- Для камер и принтеров состав устройств берётся из топологии аппарата; `XXX` и `NNN` зависят от конкретной линии.

## Технические поля ответа

| Токен | Источник | Использование backend | Что видит оператор |
|---|---|---|---|
| `DeviceName` | Ответ `QueryAll` | Имя снимка устройства (`Line`, `Printer11`, `BatchQueue`, `scada` и т. п.) | Косвенно: определяет, к какому оборудованию относятся данные |
| `Command` | Ответ `QueryAll` | Название операции, ожидается `QueryAll` | Не выводится |
| `Units` | Ответ `QueryAll` | Карта юнитов, из которой строится snapshot | Не выводится напрямую |
| `u1`, `u2`, ... | `Units` | Ключ юнита; номер извлекается из ключа и используется внутри snapshot | Не выводится напрямую |
| `State` | Юнит любого устройства | Сохраняется в snapshot как общее состояние юнита | В текущих статусах не используется напрямую |
| `Task` | Юнит любого устройства | Сохраняется в snapshot как текущая задача юнита | В текущих статусах не используется напрямую |
| `Counter` | Юнит любого устройства | Сохраняется в snapshot как счётчик операций | В текущем UI напрямую не выводится |
| `Properties` | Юнит любого устройства | Содержит теги оборудования; именованные поля нормализуются, прочие сохраняются без потери | Зависит от конкретного вложенного тега |

## Поля юнита Line

Это именованные свойства `Properties` устройства `Line`. Они описывают состояние линии и её состав.

| Токен | Использование backend | Что видит оператор |
|---|---|---|
| `ST` | Состояние линии: обычно `1` — работа, `0` — остановка | Статус линии на вкладке «Партия» |
| `Level1Printers` | Список принтеров линии; используется при определении состава оборудования | Косвенно: список принтеров на вкладке «Устройства» |
| `LineDevices` | Список всех устройств линии; по именам классифицируются принтеры и камеры | Косвенно: состав вкладки «Устройства» и состояние «Отключено» |
| `Level2Printers` | Принимается и сохраняется как группа принтеров второго уровня | В текущем UI отдельно не выводится |
| `OnChangeBatchPrinters` | Группа принтеров, связанная со сменой партии | В текущем UI не выводится |
| `OnChangeBatchCams` | Группа камер, связанная со сменой партии | В текущем UI не выводится |
| `Level1Cams` | Принимается как список камер первого уровня | В текущем runtime-составе напрямую не используется |
| `Level2Cams` | Принимается как список камер второго уровня | В текущем UI отдельно не выводится |
| `SignalCams` | Сигнальные камеры | В текущем UI не выводится |
| `LineID` | Идентификатор линии из PrintSrv | В текущем UI не выводится как отдельное поле |
| `devType` | Тип устройства/юнита | В текущем UI не выводится |
| `enableErrors` | Флаг включения обработки ошибок | В текущем UI не выводится |
| `Error` | Общий код ошибки юнита | Используется как ошибка принтера или камеры, если берётся из snapshot устройства |
| `ErrorMessage` | Текст ошибки юнита | В текущем детальном UI не выводится как отдельное поле |
| `cmdsuccess` | Результат выполнения команды | В текущем UI не выводится |
| `command` | Команда юнита | В текущем UI не выводится |
| `message` | Сообщение/результат обработки команды | В текущем UI не выводится |
| `batchId` (также принимается `batchid`) | Идентификатор партии на уровне PrintSrv | В текущем UI напрямую не выводится; данные партии берутся из `BatchQueue` или принтера |
| `CurItem` (также принимается `curitem`) | Текущий элемент; используется как резервное/операционное значение | На вкладке «Партия» используется для `initialCounter`, а в некоторых карточках — как событие/текущая партия |
| `batchIdCodesQueue` | Очередь кодов/идентификаторов партий PrintSrv | В текущем UI не выводится напрямую |
| `setBatchID` | Признак/значение установки идентификатора партии | В текущем UI не выводится |
| `devChangeBatch` | Сигнал изменения партии устройством | В текущем UI не выводится |
| `devsChangeBatchIDQueueControl` | Управление очередью смены партий | В текущем UI не выводится |

## Теги партии и очереди

### Устройство `BatchQueue`

| Токен | Использование backend | Что видит оператор |
|---|---|---|
| `Item01` ... `Item10` | Десять позиций очереди. Каждая непустая позиция разбирается как «описание \| номер партии \| дата выработки» | Вкладка «Очередь печати»: позиция, описание, партия и дата выработки |
| `kmc` | Краткий код продукта | Вкладка «Партия» |
| `description` | Наименование/описание продукта | Вкладка «Партия» |
| `ean13` | Штрихкод EAN-13 | Вкладка «Партия» |
| `batch` | Номер партии | Вкладка «Партия» |
| `dateproduced` | Дата выработки | Вкладка «Партия» |
| `datepack` | Дата фасовки/упаковки | Вкладка «Партия» |
| `dateexpiration` | Срок годности | Вкладка «Партия» |
| `place` | Площадка/место | Вкладка «Партия» |
| `itf` | Код ITF-14 | Вкладка «Партия» |
| `emk` | Значение ёмкости/объёма, передаваемое PrintSrv | Вкладка «Партия» |
| `kole` | Количество единиц в коробе/параметр упаковки | Вкладка «Партия» |
| `kolm` | Количество упаковок/параметр упаковки | Вкладка «Партия» |
| `frozen` | Признак заморозки партии | Вкладка «Партия» |
| `region` | Код региона | Вкладка «Партия» |
| `designe` | Идентификатор дизайна этикетки | Вкладка «Партия» |
| `printdm` | Признак печати DataMatrix (`1`/`0`) | Вкладка «Партия» |

### Резервные теги первого принтера

Если в `BatchQueue` нет значения, backend использует у первого принтера соответствующие ключи:

| Токен принтера | Использование backend | Что видит оператор |
|---|---|---|
| `kmc` | Краткий код продукта | Вкладка «Партия», fallback для `BatchQueue.kmc` |
| `descr` | Описание продукта; fallback для `description` | Вкладка «Партия» |
| `ean13` | EAN-13 | Вкладка «Партия» |
| `partynumber` | Номер партии; fallback для `batch` | Вкладка «Партия» |
| `dateproduced`, `datepack`, `dateexpiration` | Даты партии | Вкладка «Партия» |
| `place`, `itf`, `emk`, `kole`, `kolm` | Параметры места и упаковки | Вкладка «Партия» |
| `designe`, `printdm` | Дизайн этикетки и печать DataMatrix | Вкладка «Партия» |
| `CurItem` | Текущее изделие/счётчик первого принтера | Поле `initialCounter` на вкладке «Партия»; также используется для события принтера |

## Теги принтеров и камер

### Общие поля snapshot устройства

| Токен | Источник | Использование backend | Что видит оператор |
|---|---|---|---|
| `ST` | Принтер или камера | Работает ли устройство; для принтера также используется резервное значение из `scada` | Состояние устройства на вкладке «Устройства» |
| `Error` | Принтер или камера | Код ошибки устройства | Ошибка устройства на вкладке «Устройства» |
| `CurItem` | Принтер | Текущий элемент/партия принтера | Партия принтера и резервное значение `initialCounter` |
| `Total` | Камера | Сколько марок считано | Счётчик «считано» на карточке аппарата и в статусе камеры |
| `Failed` | Камера | Сколько марок не считано | Счётчик «не считано» на карточке аппарата и в статусе камеры |

Если устройство есть в конфигурации, но отсутствует в runtime-составе `LineDevices`, backend не читает его текущие значения и отправляет фронтенду признак `disconnected`; оператор видит «Отключено».

### Динамические ключи устройства `scada`

Для некоторых устройств те же показатели берутся из `scada` как fallback. Формат ключа зависит от устройства:

| Шаблон токена | Для каких устройств | Использование backend | Что видит оператор |
|---|---|---|---|
| `LineDevNNNST` | Принтеры (`Printer11` → `LineDev011`) | Резервное состояние принтера, если в snapshot принтера нет `ST` | Состояние принтера |
| `DevXXXCounterGeneral` | Камеры агрегации, box-камеры и EAN-чекеры | Резервный счётчик считанных марок | Счётчик «считано» |
| `DevXXXCounterMissing` | Те же камеры | Резервный счётчик непрочитанных марок | Счётчик «не считано» |
| `DevXXXST` | Те же камеры | Резервное состояние камеры | Состояние камеры |
| `DevXXXError` | Те же камеры | Резервный код ошибки камеры и флаг общей ошибки | Ошибка камеры |

Соответствие `XXX` вычисляется по позиции устройства в составе линии: агрегационные камеры используют `041`, `043`, `045` и далее; box-камеры — `042`, `044`, `046` и далее; `CamEanCheckerN` — `07N` (например, `CamEanChecker1` → `Dev071`).

## Теги устройства `scada`

### Флаги ошибок устройств

Backend перебирает свойства устройства `scada` и обрабатывает только активные значения: ключ должен оканчиваться одним из суффиксов ниже, а значение должно быть не пустым и не равно `0`.

| Шаблон токена | Смысл ошибки | Что видит оператор |
|---|---|---|
| `DevXXXConnection` / `LineDevNNNConnection` | Нет связи с устройством | Активная ошибка и алерт по устройству |
| `DevXXXFail` / `LineDevNNNFail` | Нет кодов маркировки | Активная ошибка и алерт |
| `DevXXXDublicate` / `LineDevNNNDublicate` | Одинаковые коды маркировки | Активная ошибка и алерт |
| `DevXXXDiffEan` / `LineDevNNNDiffEan` | EAN в коде упаковки не совпадает с идентификатором партии | Активная ошибка и алерт |
| `DevXXXWork` / `LineDevNNNWork` | Нет данных с устройства | Активная ошибка и алерт |
| `DevXXXData` / `LineDevNNNData` | Нет данных с устройства, дополнительный флаг | Активная ошибка и алерт |
| `DevXXXBatch` / `LineDevNNNBatch` | Не совпадает идентификатор партии | Активная ошибка и алерт |
| `DevXXXError` / `LineDevNNNError` | Общая ошибка устройства | Активная ошибка и алерт |

В интерфейсе активные ошибки попадают в:

- алерт/индикатор ошибки аппарата;
- вкладку «Журнал» как сообщение вида «устройство: описание ошибки»;
- статус устройства на вкладке «Устройства», если ключ используется как fallback для конкретной камеры.

Имя `Dublicate` сохранено в документе в оригинальном написании PrintSrv.

## Поля, которые принимаются, но не выводятся напрямую

`PropertiesDTO` автоматически сохраняет любые неизвестные ключи `Properties` в `rawProperties`. Это нужно для device-specific полей камер, принтеров, `BatchQueue` и будущих вариантов конфигурации. В качестве примеров в снимках встречаются:

- `Succeeded`, `kd`, `LastRead` — дополнительные поля камер;
- `ip`, `les`, `printpath`, `owner`, `templatecode`, `load` — служебные поля принтеров;
- `ean`, `batch`, `dtv`, `lineerr`, `batchid` — поля снимка `scada`.

На текущий момент backend не использует эти примеры для формирования отдельного поля UI. Сам факт сохранения неизвестного ключа не означает, что он уже отображается на фронтенде.

## Краткий вывод для согласования

Для проверки с отделом маркировки в первую очередь стоит подтвердить смысл и доступность следующих групп:

1. `ST` линии и устройств — корректно ли отображается работа/остановка.
2. `description`/`descr`, `ean13`, `batch`/`partynumber`, даты и упаковочные параметры — всё ли необходимое по партии выведено на вкладку «Партия».
3. `Item01` ... `Item10` — состав и формат очереди печати.
4. `Total` и `Failed` — корректность счётчиков камер.
5. Флаги `Connection`, `Fail`, `Dublicate`, `DiffEan`, `Work`, `Data`, `Batch`, `Error` — полнота отображения ошибок.
6. `Level1Printers` и `LineDevices` — соответствует ли фактический состав оборудования тому, что показывается на вкладке «Устройства».
